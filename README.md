# Skhoron Vault

Локальный менеджер паролей. Часть экосистемы Skhoron.

## Architectural invariant: Zero Network

`AndroidManifest.xml` не запрашивает `INTERNET` permission. Без него ОС на
уровне ядра блокирует сокеты для UID этого приложения — это архитектурный
инвариант, а не настройка по умолчанию.

## Статус: v0.4

- **Крипто**: Argon2id (64MB/3 итерации) + **ChaCha20-Poly1305 (RFC 7539,
  96-бит nonce)** через BouncyCastle, чистый JVM без NDK. Ранее в README
  ошибочно указывался XChaCha20-Poly1305 (192-бит nonce) — это не совпадало
  с реализацией; исправлено
- **Разделение ключей**: два независимых подключа через HKDF —
  `KeyContext.SQLCIPHER` для шифрования файла БД и
  `KeyContext.FIELD_ENCRYPTION` для шифрования отдельных полей
- **Хранилище**: Room поверх SQLCipher. Без `fallbackToDestructiveMigration()`
  — несовместимая схема приведёт к явному падению, а не молчаливому
  удалению данных
- **Разблокировка**: мастер-пароль конвертируется в байты напрямую из
  `CharArray` (без промежуточного `String` в куче JVM), затирается в
  `finally` даже при исключении
- **Panic wipe**: 10 неверных попыток подряд → необратимое удаление файла БД
  и локальных настроек
- **Auto-lock**: монотонные часы (`SystemClock.elapsedRealtime()`), не
  подвержены переводу wall-clock времени. Настраиваемый таймаут (1–30 минут)
- **FLAG_SECURE**: список паролей и генератор недоступны для скриншотов и
  screen recording
- **Автозаполнение**: `AutofillService`, датасет — только при точном
  совпадении домена (anti-phishing invariant)
- **Локальный бэкап**: экспорт делает WAL checkpoint перед копированием
  (иначе несохранённые в `-wal` транзакции не попали бы в бэкап). Импорт
  атомарный — временный файл валидируется полностью, и только потом
  заменяет рабочую БД; соль обновляется в настройках последней, после
  успешной замены файла
- **Генератор паролей**: SecureRandom, дефолт 64 символа (~419 бит)

## Известное ограничение (осознанное, не баг)

Сгенерированный/расшифрованный пароль в какой-то момент существует как
`String` в памяти для отображения в UI — Compose `TextField` работает
только со `String`, обойти это без кастомного текстового поля поверх
`CharArray`-буфера штатными средствами нельзя. Мастер-пароль этого
ограничения не имеет (см. выше).

Метаданные записи (`label`, `username`, `domainHint`) хранятся в таблице не
зашифрованными отдельно от пароля — но SQLCipher шифрует файл БД целиком,
так что без знания master key метаданные так же недоступны, как и пароли.
Если master key известен атакующему, он тривиально выводит оба подключа
(SQLCipher и field-encryption) из одного источника через HKDF — то есть
раздельное шифрование метаданных не добавило бы реальной защиты в этой
модели угроз, только усложнило бы поиск по домену для автозаполнения.

## Roadmap / не реализовано

- Экран просмотра и копирования отдельной записи
- Диалог подтверждения сохранения в AutofillService (сейчас сохраняет сразу)
- Аудит слабых/повторяющихся паролей, TOTP/2FA, офлайн-проверка утечек
- Типы записей "Карта" (номер/срок/CVC) — обсуждались, ещё не реализованы

## Сборка

Требуется Android Studio (Koala или новее).

1. `File → Open` — открыть папку `SkhoronVault/`
2. Дождаться `Gradle Sync`
3. `Build → Build Bundle(s) / APK(s) → Build APK(s)`
4. Готовый файл: `app/build/outputs/apk/debug/app-debug.apk`
5. Установить на устройство
6. Настройки → Система → Языки и ввод → Автозаполнение → выбрать
   Skhoron Vault

## CI

`.github/workflows/ci.yml` — сборка + lint + проверка architectural
invariant (отсутствие `INTERNET` permission и сетевых классов в исходниках).
Использует `gradle/actions/setup-gradle` с явно закреплённой версией Gradle
8.7 — не зависит от закоммиченного Gradle Wrapper.
